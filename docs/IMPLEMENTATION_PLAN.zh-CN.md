# Shot Form Coach 实施计划

本计划按依赖交付可在本地测试的 V1，然后用新增数据决定后续模型与训练功能。每一步都产生可查看的产物和验收证据，进度以实际完成的检查更新。

## V1 交付目标

用户导入一次投篮或现有 Workbench 的一组片段，系统自动提出动作阶段、计算可见的投影指标，并显示有证据的观察。用户可以选择自己的另一球作为参照，用一两次点击修正离手区间，导出文字、对比图和慢放视频。英语/中文界面、任务进度和模型调用记录保留。

首个验证闭环为“出手后手臂位置变化与个人重复性”。观察、训练假设和训练效果分别呈现。

## M1 媒体与状态底座

- 配置新项目自己的数据目录和端口，沿用 Python/FastAPI、React/TypeScript、SQLite 与 FFmpeg 的技术方向。
- Workbench adapter 读取导出合同并复制选中片段，记录上游 run/event ID、内容哈希、源时间偏移和原帧编号。独立上传建立自己的片段时间轴。
- 解码以真实 PTS 建立帧索引；浏览器预览的时间映射独立校验。缩放、裁剪和旋转变换显式保存。
- 后台任务与可恢复状态分开；文件产物通过已登记的资源 ID 读取。

通过条件：重复导入可识别、路径不越界、VFR 时间不按平均 FPS 重新编造、上传失败后可重新选择素材。

## M2 自动观察与测量

- 姿态采用离线 VIDEO 模式，按实际时间戳处理。先选择主要人物，再保存原始关键点、可见性和版本。V1 使用窗口聚合并断开缺失轨迹；时序滤波另作后续对照。
- 球检测建立候选轨迹。近手到分离的转换仅用于提出离手区间，识别失败时保留未知状态；伸展高点与物理离手不混为同一字段。
- V1 首批五项：较早/较晚腕部高度、腕部高度变化、投影肘部角度变化、下沉低点到离手时长。躯干和足部稳定性暂列后续，需要可见性与测量定义验证。采用有效帧比例与质量条件，不给统一全身总分。
- 单目 world 坐标只保留为估计输出，首版评估使用可核对的投影量。

通过条件：在真实样例上检查骨架和球候选；低可见性、切断的后续阶段和不确定离手都有明确的结果状态。

## M3 可选修正与版本

- 时间轴可以按源帧前后移动；选择最后接触与首次明确分离，或给出带一帧不确定性的单帧锚点。
- 创建新阶段版本，保留模型原始提议与操作者来源。
- 用已有姿态/球缓存重算，重新生成参照对齐和报告；新旧版本可比较。
- 参照只作为所选属性的比较样本。投篮侧、情境与视角不匹配时降低比较等级。

通过条件：刷新后修正仍在；异步旧结果无法覆盖修正后的当前结果；源时间与参照时间各自可追溯。

## M4 三种报告与训练提示

- 先用确定性规则和已有教学来源形成观察与候选提示，数值取自 Measurement。
- 模型可解释结构化证据与选择提示，不能补写未测量的数字或独断未进原因。
- 复盘展示属性、证据和差异；练习只聚焦一个短提示，并为后续记录提示风格和反馈时机留下字段。
- 文字、图与视频由统一 render_spec 生成，标记参考/示意、慢放速度和可见窗口边界。

通过条件：导出的文件真实可播放/查看；更换参照或阶段版本后，所有产物同步；缺少参考时也能输出合格的观察报告。

## M5 模型与交付检查

- 首版保持本地分析可运行；Gemini 辅助在配置与模式选择后启用。Astra/Qwen 通过同一未来 adapter 合同接入，先按评测计划比较。
- 提交前保存请求意图和预算；保存输入帧引用、响应、usage 和价格依据。结果未知时阻止自动重发，已收到 usage 即使验证失败也保留。
- 测试覆盖时间、质量、版本、请求结果与费用这些会误导用户的边界；不以大量镜像实现的测试代替真实样例检查。
- 实际浏览器检查导入、自动完成、修正、参照、下载、取消/失败恢复、英文/中文、桌面及窄屏。

通过条件：启动器就绪检查、针对性测试、前端构建、真实本地视觉样例和报告解码通过。模型比较和教练效果尚未验证的部分在交付记录中单列。

## 数据依赖与下一步取舍

现有 6 球用于工程回归和输出检查。达到专项动作评估门槛，需要跨场次样本、独立阶段标注和教练判断；训练效果需要用户实际重拍记录。自动阶段修正产生的是时间标签，不能当成正确投篮姿势的标签。

若姿态或球检测在新视角明显失效，先修正采集条件/模型选择，再扩大规则覆盖。首版工程验收与 M6/M7 的科学验收分别记录。

## 本轮实施记录

M0 到 M4 已落地；M5 的本地闭环、请求边界测试、双语界面和启动器已落地。21 项边界测试与前端构建通过，6 段真实投篮生成报告；在浏览器检查阶段修正、刷新持久化、参照选择、中文文字下载、逐帧与 390px 窄屏。视频完整解码及逐输出帧源引用校验通过。详见 [V1 验证记录](VALIDATION_V1.md)。

Gemini / Astra 当前是受输入帧 ID 约束的图像序列 adapter；Astra 已有 OpenAI API 与 Codex 订阅两种通道。Codex 使用无个人内容的合成图片完成一次实时调用，真实投篮片段尚未通过该通路验证。原生视频 transport 及模型横评归入 M6。手动阶段修正限于离手区间，其他阶段修正作为下一步小迭代。训练日志/练习模式尚未落地，不把示意图当作库里实测姿态。M6/M7 需要新增独立标注与实际重拍记录，本轮不能用既有六球证明模型最优或训练效果。
